# Cursor: история чата, сессии и кеш

Dev-патч **1.17.17**, 2026-10-15. Стабильный релиз остаётся 1.17.3.

Проверка по сценариям Coco выявила три проблемы: новый SDK-агент на каждый
запрос, молчаливое удаление начала длинной истории и отсутствие подключения
нативных SDK usage/cache counters к общей диагностике.

## Поведение после исправления

- Первый переход из Codex, Coco или Claude получает доступную видимую историю
  из общего workspace-журнала. Восстанавливаются и ранние сообщения, которые
  интерфейс уже перестал передавать, если они были записаны этим расширением.
- Следующий запрос продолжает того же SDK-агента и передаёт новые сообщения.
  Возврат после другого провайдера добавляет его новые сообщения и результаты
  инструментов. Завершённые собственные вызовы повторно не выполняются.
- После reload расширение вызывает `Agent.resume` с ID завершённой сессии и
  актуальными callback tools. При отказе восстановления создаётся новый агент
  с полной доступной историей; диагностика показывает `resume-fallback`.
- Профиль, ключ, модель/параметры, рабочая папка и conversation ID участвуют
  в изоляции. Правка старой пользовательской ветки создаёт новую сессию.
- Переключение провайдера прерывает только незавершённый Cursor run этого
  чата. Старые результаты отменённых инструментов отклоняются. Завершённая
  сессия остаётся доступна для возврата.
- Команды, файлы, правки и остальные действия выполняют инструменты VS Code.
  Built-in shell/filesystem/web, внешние MCP и настройки проекта не включаются.

## Большая история

SDK получает всю сериализованную историю без удаления начала/середины.
Большой перенос разбивается на запросы, ограниченные рабочим контекстом,
резервом нативного промпта и схемами инструментов; максимум текста одного
переноса — 500 тысяч символов. Это ограничение **одного запроса**, не общего
журнала. Импорт сохраняет Unicode и изображения, скрывает промежуточные ACK
и передаёт пустой каталог callbacks. После импорта продолжается последний
пользовательский запрос.

`llamacpp.cursorMaxHistoryImportParts`: по умолчанию **16**, диапазон 1–128.
Каждая часть может расходовать токены. Превышение останавливается до inference
и сообщает путь к полной локальной копии. Большие результаты инструментов
также сохраняются полностью; в модель идут начало, конец и путь для чтения.

На каждом SDK-запросе доступен путь к актуальному JSON-журналу всего видимого
чата. После нативной компактации модель может перечитать точные детали через
VS Code file/search tools. Конечное окно модели и серверная компактация остаются:
дисковый журнал не означает, что весь многомиллионный чат одновременно находится
в attention модели. Историю, которую интерфейс никогда не передавал расширению,
и скрытые рассуждения другого провайдера восстановить невозможно.

Chat-only Cloud fallback не имеет локальных инструментов для такого архива:
он явно отклоняет переполнение контекста вместо молчаливого удаления истории.

## Usage и кеш

Источник — `RunResult.usage` официального `@cursor/sdk` 1.0.37.
Проверена реализация SDK: `totalTokens = inputTokens + outputTokens +
cacheReadTokens + cacheWriteTokens`; SDK `inputTokens` содержит свежий вход.
Расширение считает общий вход как свежий + cache read + cache write **один раз**.

- Quick Access показывает Tokens/Prompt Cache/Throughput у соответствующего
  API-профиля; история расхода записывается в категорию API profiles.
- Session Diagnostics показывает Cursor session mode, свежий вход, cache read,
  cache creation и долю чтения кеша. Импорт и основной запрос входят в один
  логический turn. Число prompts не выдаётся за число внутренних backend calls.
- Отсутствующие или некорректные counters остаются unreported. При частично
  отсутствующей usage сумма помечается estimated, aggregate cache скрывается.
- Cumulative usage не превращается в заполненность контекста. SDK-снимок
  occupancy в этом адаптере не получен; максимум берётся из каталога/настроек.
- Warm/restored сессия сама по себе не доказывает cache hit. Кеш выдаёт сервер,
  его срок жизни и причина низкого hit rate неизвестны. Кеш Codex/Coco не
  переносится в Cursor; переносится доступная история.

Баланс и Admin API удалены. Для token/cache метрик Admin token не требуется.

## Хранение

Workspace storage содержит `cursor-sdk/` (нативный JSONL store и архивы) и
`chat-history/` (общий видимый журнал, включая изображения). Это локальные
копии содержимого чата, не файлы репозитория. Удаление workspace storage удалит
их. Автоматическая очистка архивов сейчас не реализована.

WorkspaceState содержит только ID, хеши пользовательских якорей/конфигурации
и время. Перед inference completed checkpoint удаляется и запись ожидается:
незавершённый после сбоя run не восстанавливается как завершённый. Не более
32 checkpoints за 7 дней; до 8 idle агентов в памяти, idle timeout 30 минут.
Chat API key остаётся в прежнем SecretStorage и не записывается в checkpoint.

## Верификация

Автоматические проверки покрывают Codex → Cursor через workspace-журнал после
reload, warm deltas, native resume/fallback, обновление callbacks и окружения,
раздельные чаты/ключи/профили, отмену и stale results, большие импорты, изображения,
точный архив tool results, ошибки durable storage, native usage и рендер панели.
Настоящий установленный SDK проверяется через `Agent.create` → `Agent.resume`
с callback-only конфигурацией **без генерации**.

Проверки 1.17.17: TypeScript и ESLint прошли; полный suite — **703 passing,
8 pending** на VS Code 1.131.0 и **701 passing, 10 pending** на установленном
VS Code 1.141.0. Pending включает opt-in платные проверки и проверки bundle,
не применимые к выбранной версии; ошибок нет.

Реальный inference в этой проверке не запускался: отдельная тестовая среда
не имеет SDK-входа или переменной с chat API key. Не утверждается измеренный
cache hit на сервере Cursor. Для воспроизводимой проверки добавлен opt-in
`Cursor real runtime` в `src/test/cursor-runtime.test.ts`: три коротких запроса
проверяют сохранение случайного маркера на cold/warm/reload и печатают только
native counters. Нужны `AAB_CURSOR_REAL_CONTINUITY=1`, точный `AAB_CURSOR_MODEL`
и chat key в `AAB_CURSOR_KEY` либо `CURSOR_API_KEY`, заданные пользователем вне
чата. Обычный CI пропускает этот платный тест; ключи не печатаются.

После локальной установки перезагрузите окно VS Code и выберите Cursor
в существующем чате. Диагностика появится для новых запросов, без выдуманных
исторических counters.
