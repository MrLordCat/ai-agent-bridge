# Cursor: история чата, сессии и кеш

Локальное исправление **1.18.6**, 2026-10-19; вошло в стабильную версию
**1.19.0**.

После `Premature close` расширение проверяет не только завершённые native
callbacks, но и события, выданные после последнего checkpoint. Если такие
вызовы уже завершились в VS Code, их результаты передаются как история при
следующем новом пользовательском сообщении. Выполнять инструменты повторно
не требуется. [Разбор и условия восстановления](CURSOR_PREMATURE_CLOSE.md).

В запросах нового хоста встречается стандартное поле `_conversationId`
без добавляемого старым патчем `_copilotConversationId`. До 1.18.5
маршрутизатор терял ID: общий журнал не подключался, а Cursor считал запрос
новым и останавливал перенос 1,45 млн символов лимитом 64 000.
Теперь ID нормализуется до выбора провайдера, журнала и отмены чужих циклов;
сохраняются прежние ключи workspace/profile/chat. Валидный старый ID имеет
приоритет; пустые и некорректные значения нового поля не используются.

Это лимит расширения на автоматический холодный replay, не предел модели
Cursor. `llamacpp.cursorMaxColdHistoryChars` остаётся 64 000: повышение
разрешило бы платную отправку всей истории, но не исправляло бы утрату ID.
Для восстановленной сессии этот холодный лимит не применяется — отправляется
только продолжение в пределах рабочего контекста. Если хост вообще не передал
ID, ошибка теперь прямо объясняет причину и не начинает inference.

В проблемном чате ID даёт точный прежний ключ привязки. На временной копии
хранилища настоящий SDK восстановил того же агента и неизменные байты
checkpoint: ноль сетевых обращений и генераций, исходное хранилище не менялось.
Эта проверка подтверждает native resume; серверный cache hit не измерялся.

Проверки 1.18.5: **731 passing, 8 pending** на VS Code 1.131.0;
**729 passing, 10 pending** на установленной VS Code. TypeScript, ESLint,
metadata и diff-check прошли. Проверен полный маршрут нового ID для истории
на 1,45 млн символов, возврат результата инструмента и ещё один reload.

Диагностика cache hit и разбор реального случая 70,04%:
[CURSOR_CACHE_RESEARCH.md](CURSOR_CACHE_RESEARCH.md). Восстановление native
сессии сохраняет историю, а серверный prompt cache имеет отдельный жизненный цикл.

В рабочем чате 1.18.0 обнаружены два разных SDK-агента с одинаковой моделью
и параметрами, повторные полные архивы и несколько платных запросов импорта.
Обновления каталога между этими двумя turns в доступном логе не было.
Точную причину первоначального отказа checkpoint задним числом установить
не удалось. Проверки истории зависели от представления сообщений; патч
нормализует якоря и запрещает неподтверждённый полный повтор до inference.

Отдельно подтверждена ошибка диагностики: нативный input уже включал кеш,
а расширение прибавляло его снова. Это завышало показанные токены; реальный
дополнительный расход создавали запросы импорта, а не сама ошибка счётчика.

После 1.18.1 выявлена отдельная причина отказа после reload: workspaceState
уже не содержал привязки чата, хотя JSONL-store сохранил завершённый native run
и его checkpoint. Указатель checkpoint в записи SDK-агента также мог отсутствовать.
В 1.18.2 привязка сохраняется отдельным атомарным файлом, а указатель native state
восстанавливается из подтверждённого завершённого run. Простой запрет дорогого
cold start сам по себе эту потерянную привязку не исправлял.

## Поведение после исправления

В 1.18.3 исправлена обработка сбоя во время tool cycle. В рабочем SDK-журнале
первичная ошибка была `[resource_exhausted] Error`; последующие повторы результатов
инструментов скрывали её сообщением `tool session is no longer active`.
Cursor не сообщил, какой именно ресурс исчерпан. Расширение не повышает лимиты
сервера и не запускает автоматические повторные запросы модели.

Если все native tool calls получили terminal result, checkpoint failed run
сохраняется для следующего явного пользовательского сообщения. При ожидающих
результатах такой checkpoint не принимается. Повтор той же партии результатов
возвращает исходную ошибку, в том числе после reload, без нового SDK run.
Это сведения об ошибке и ID вызовов, а не повтор исполнения инструментов.

Для уже сломанного 1.18.2 inflight binding проверяется совпадение начального
checkpoint и всех callback-вызовов с видимым журналом, включая аргументы,
число повторов и результаты. Порядок параллельных callbacks может отличаться.
В реальном случае подтверждены все 84 завершённых вызова; новый native checkpoint
содержит их результаты и позволяет не возвращаться к состоянию до этой работы.

Ограниченный журнал исходных ошибок содержит максимум 32 conversations и
512 call IDs на запись. Дисковые записи старше суток не восстанавливаются.
Они изолированы по identity профиля, модели и чата. Тексты результатов и API
keys в эти записи не включаются.

Проверки: Cursor suite — **70 passing, 1 pending**; полные прогоны —
**726 passing, 8 pending** на VS Code 1.131.0 и **724 passing, 10 pending**
на VS Code 1.141.0. Metadata, TypeScript и ESLint прошли. Настоящий SDK
восстановил failed checkpoint рабочего чата на временной копии: тот же агент,
неизменные байты native state, 84 завершённых callback-вызова, ноль запросов
генерации при заблокированной сети. Платные opt-in проверки не запускались.

- Первый переход из Codex, Coco или Claude получает доступную видимую историю
  из общего workspace-журнала. Восстанавливаются и ранние сообщения, которые
  интерфейс уже перестал передавать, если они были записаны этим расширением.
- Следующий запрос продолжает того же SDK-агента и передаёт новые сообщения.
  Возврат после другого провайдера добавляет его новые сообщения и результаты
  инструментов. Завершённые собственные вызовы повторно не выполняются.
- После reload расширение вызывает `Agent.resume` с ID завершённой сессии и
  актуальными callback tools. Это восстановление native state без отдельного
  импорта. Используется тот же непрозрачный checkpoint SDK, а отправляются только
  новые сообщения. При отказе resume сохраняется checkpoint и выводится причина;
  автоматическая замена восстановления полным prefill запрещена.
- Reload или отмена следующего запроса сохраняют последний завершённый native
  checkpoint. Незавершённые сообщения остаются в видимом журнале и добавляются
  после него. Исторические действия не запускаются автоматически повторно.
- Утерянная привязка 1.18.0 может быть восстановлена по архиву именно этого чата,
  совпадению старых пользовательских сообщений и уникального завершённого ответа,
  модели, workspace и времени первого запроса. Неоднозначные, ошибочные и
  содержащие только импорт агенты не выбираются. Содержимое checkpoint не меняется.
- Профиль, ключ, модель/параметры, рабочая папка и conversation ID участвуют
  в изоляции. Обновление каталога, порядок параметров, доступность callbacks
  и рабочий бюджет текста сами по себе native state не сбрасывают.
- Разбиение TextParts и изменяемые host-context блоки не меняют канонические
  пользовательские якоря. Если старый префикс перепакован, но последний
  завершённый пользовательский якорь сохранён, отправляется только продолжение.
  Несопоставимая правка ветки останавливается до inference; завершённая сессия
  сохраняется. Автоматического полного повторения истории в этом случае нет.
- Завершённые checkpoints 1.18.0 мигрируют на новые якоря при подтверждённой
  совместимости. Предварительная ошибка бюджета не закрывает тёплого агента.
- Переключение провайдера прерывает только незавершённый Cursor run этого
  чата. Старые результаты отменённых инструментов отклоняются. Завершённая
  сессия остаётся доступна для возврата.
- Команды, файлы, правки и остальные действия выполняют инструменты VS Code.
  Built-in shell/filesystem/web, внешние MCP и настройки проекта не включаются.

## Большая история

С версии 1.18.14 применяется [общий контекст](SHARED_CONTEXT.md), как для Codex
и Coco: один журнал, общий токенный бюджет и генератор сводки. Независимый
`cursorMaxColdHistoryChars` больше не используется. Описание лимитов символов
ниже относится к предыдущей реализации 1.18.13.

Для истории в пределах выбранного лимита SDK получает сериализованный текст
целиком. С версии 1.18.13 длинный структурированный холодный перенос локально
сокращается: последний запрос остаётся целым, полный оригинал и старые
изображения сохраняются в доступном модели архиве. Модель получает выдержки
старых сообщений и явную ссылку на архив. На запрос создаётся **один SDK run**, без дополнительных
импортов с ACK. Внутри него SDK может выполнять несколько model/tool iterations.
Произвольный предел 500 тысяч символов удалён. Текст должен помещаться в
рабочий бюджет с резервом для нативного промпта и схем инструментов; допускается
до пяти изображений. Переполнение останавливается до inference с полным архивом.

`llamacpp.cursorMaxColdHistoryChars`: по умолчанию **64 000 символов**, диапазон
4 096–3 000 000. Ограничивает историю только для новой сессии. Отказ
`Agent.resume` не создаёт новую сессию. Больший структурированный cold start
сохраняет полную копию и подготавливает ограниченный перенос, показывая объём
и путь в Chat. Если один текущий запрос превышает предел или формат промпта
неизвестен, генерация не запускается. Увеличение настройки явно разрешает
больший платный prefill. Warm/restored delta
не подчиняется холодному пределу, но проверяется по рабочему бюджету модели.

`llamacpp.cursorMaxHistoryImportParts` устарела и игнорируется. Ни старое
значение 16, ни повышение до 128 не включают импорт по частям. Большие
результаты инструментов сохраняются полностью; модель получает начало,
конец и путь для чтения.

На каждом SDK-запросе доступен путь к актуальному JSON-журналу всего видимого
чата. После нативной компактации модель может перечитать точные детали через
VS Code file/search tools. Конечное окно модели и серверная компактация остаются:
дисковый журнал не означает, что весь многомиллионный чат одновременно находится
в attention модели. Историю, которую интерфейс никогда не передавал расширению,
и скрытые рассуждения другого провайдера восстановить невозможно.

Chat-only Cloud fallback не имеет локальных инструментов для такого архива:
он явно отклоняет переполнение контекста вместо молчаливого удаления истории.

## Usage и кеш

Источник — `RunResult.usage` официального `@cursor/sdk` 1.0.37.
Нативные результаты рабочего чата подтверждают: `inputTokens` уже содержит
cache read/write. Комментарии типов и SDK-helper `totalTokens`, прибавляющий кеш
снова, расходятся с наблюдаемыми значениями. Адаптер принимает оба известных
формата total, проверяет согласованность и использует input без прибавления кеша.
Например, input 224 876, read 4 121, write 220 751 означают **4 свежих токена**.
Исторические агрегаты автоматически не пересчитываются: в них смешаны разные
источники, и деление общей суммы пополам было бы некорректным.

- Quick Access показывает Tokens/Prompt Cache/Throughput у соответствующего
  API-профиля; история расхода записывается в категорию API profiles.
- Session Diagnostics показывает Cursor session mode, свежий вход, cache read,
  cache creation и долю чтения кеша, причину продолжения/новой сессии. Первый
  cold start отделён от session-not-reused. Число SDK prompts не выдаётся
  за число внутренних backend calls.
- Отсутствующие или некорректные counters остаются unreported. При частично
  отсутствующей usage сумма помечается estimated, aggregate cache скрывается.
- Cumulative usage не превращается в заполненность контекста. SDK-снимок
  occupancy в этом адаптере не получен; максимум берётся из каталога/настроек.
- Warm/restored сессия сама по себе не доказывает cache hit. Кеш выдаёт сервер,
  его срок жизни и причина низкого hit rate неизвестны. Кеш Codex/Coco не
  переносится в Cursor; переносится доступная история.

Баланс и Admin API удалены. Для token/cache метрик Admin token не требуется.

## Хранение

Workspace storage содержит `cursor-sdk/` (нативный JSONL store и архивы) и
`chat-history/` (общий видимый журнал, включая изображения). Это локальные
копии содержимого чата, не файлы репозитория. Удаление workspace storage удалит
их. Автоматическая очистка архивов сейчас не реализована.

WorkspaceState и `cursor-sdk/completed-sessions.json` содержат только ID,
хеши пользовательских якорей/конфигурации, ссылку на завершённый native checkpoint
и время. Дисковая запись атомарна и завершается до отправки следующего запроса;
при потере workspaceState она восстанавливает привязку. Во время inference
последний завершённый checkpoint остаётся сохранённым с отметкой inflight.
После сбоя восстанавливается он, а не частично изменённое состояние. Не более
32 checkpoints за 7 дней; до 8 idle агентов в памяти, idle timeout 30 минут.
Chat API key остаётся в прежнем SecretStorage и не записывается в checkpoint.

## Верификация

Автоматические проверки покрывают Codex → Cursor через workspace-журнал после
reload, warm deltas, native resume/fallback, обновление callbacks и окружения,
раздельные чаты/ключи/профили, отмену и stale results, одноразовый большой prefill,
ограниченный cold handoff и отказ слишком большого текущего запроса, изображения, точный архив tool results, ошибки durable
storage, native usage и рендер панели. Отдельно проверяются миграция checkpoints,
канонические якоря, retained-tail продолжение и сохранение агента после отказа
бюджета. Native counters из рабочего чата закреплены как regression fixture.
Настоящий установленный SDK проверяется через `Agent.create` → `Agent.resume`
с callback-only конфигурацией **без генерации**.

Целевые проверки 1.18.2: TypeScript и ESLint прошли; Cursor suite —
**65 passing, 1 pending**. Включены потеря Memento, повторный reload чата с 1,4 млн
символов, прерывание tool run, отказ resume и проверка native JSONL-store.
Полные прогоны: **721 passing, 8 pending** на VS Code 1.131.0 и
**719 passing, 10 pending** на VS Code 1.141.0. Metadata и ESLint также прошли.
Платные opt-in проверки не запускались.
На данных проблемного чата локально подтверждена пригодная завершённая сессия:
18 старых пользовательских turns остаются в native state, а продолжению нужны
только три новые записи видимого журнала. Проверка не отправляла запросов модели
и не изменяла исходное хранилище.

Дополнительно настоящий SDK дважды выполнил `Agent.resume` на временной копии
этого хранилища с запрещённой сетью: ID агента и байты native checkpoint
сохранились. Ноль запросов генерации. Это подтверждает локальное восстановление;
наличие и срок жизни серверного prompt cache таким тестом не измеряются.

Реальный inference в этой проверке не запускался: отдельная тестовая среда
не имеет SDK-входа или переменной с chat API key. Не утверждается измеренный
cache hit на сервере Cursor. Для воспроизводимой проверки добавлен opt-in
`Cursor real runtime` в `src/test/cursor-runtime.test.ts`: три коротких запроса
проверяют сохранение случайного маркера на cold/warm/reload и печатают только
native counters. Нужны `AAB_CURSOR_REAL_CONTINUITY=1`, точный `AAB_CURSOR_MODEL`
и chat key в `AAB_CURSOR_KEY` либо `CURSOR_API_KEY`, заданные пользователем вне
чата. Обычный CI пропускает этот платный тест; ключи не печатаются.

После локальной установки перезагрузите окно VS Code и выберите Cursor
в существующем чате. Диагностика появится для новых запросов, без выдуманных
исторических counters.
