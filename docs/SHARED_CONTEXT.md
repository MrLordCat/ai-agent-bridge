# Общий контекст провайдеров — 1.18.15

Назначение переключения моделей: при rate limit продолжить тот же рабочий чат
у другого провайдера с прежними требованиями, решениями и результатами действий.

## Источник истории

`CompositeChatModelProvider` восстанавливает workspace-журнал до выбора входа
любого адаптера: Codex, Coco, Cursor, Claude, HTTP/local. Раньше восстановленная
история подставлялась выборочно, поэтому провайдеры могли получить разные окна
одного чата. Теперь исходная семантическая история одна.

Журнал сохраняет типы сообщений, вызовы и результаты инструментов, исходные
изображения. Укороченное окно от хоста дополняется по стабильным пользовательским
якорям. Одинаковые системные снимки не накапливаются при смене провайдера;
актуальный системный блок заменяет прежний. Правки с известным общим началом
по-прежнему создают ветку без оставленных сообщений отменённого продолжения.

## Первый запрос нативному провайдеру

Codex, Coco и Cursor используют `context/provider-handoff.ts`:

1. Рассчитывается общий бюджет истории после резервов для вывода, схем
   инструментов, нативных инструкций и запаса.
2. Старые длинные результаты инструментов сокращаются по одной политике.
   Если история всё ещё велика, используется детерминированная сводка старого
   контекста по тому же генератору, что применялся для Codex, плюс недавний хвост.
3. Текущий запрос и текущие изображения сохраняются целиком. Если они сами не
   помещаются, запрос останавливается до inference, а не молча обрезается.
4. Полный оригинал остаётся в общем журнале и архиве. Исторические изображения
   доступны как точные файлы по ссылкам; их base64 не размножается в промпте.

Отдельные ограничения холодного старта Cursor 64 000 символов и Coco 1 000 000
символов больше не выбирают содержимое. Протокольное кодирование, служебный
промпт и доступные возможности backend остаются специфичными провайдеру.
Одинаковый исходный контекст не означает одинаковые wire JSON или токенизаторы.

## Настройка

`llamacpp.sharedContextLength` — один рабочий контекст **в токенах** для Codex,
Claude, Coco и Cursor. Значение `0` наследует `codexWorkingContextTarget`,
сохраняя прежний пользовательский выбор Codex: например, при
`codexWorkingContextTarget = 475000` наследуется 475 000, пока не задан
отдельный shared target. Из него вычитаются одинаковые резервы, поэтому бюджет
самой истории меньше этого числа. Меньшее реальное окно выбранной модели или
профиля остаётся физическим пределом; расширение не может увеличить его.

Лимит меняется одним ползунком в **Quick Access → Providers → Shared Context**
(панель Provider Context). Отдельных ползунков Claude и Codex больше нет;
`claudeContextLength` устарел и не читается. Панель показывает итоговое значение
каждого провайдера. Каждый адаптер объявляет VS Code окно
`min(лимит, реальное окно модели)`, поэтому индикатор контекста Chat одинаков
после переключения. Профиль Cursor вместо собственного ползунка показывает
общее значение; у прочих API-профилей ползунок остаётся.

Оценка общая и консервативная: UTF-8 bytes / 2 для текста, отдельный запас для
изображений и оболочек сообщений. Это **оценка**, не точный tokenizer конкретной
модели. Значения usage/cache за несколько model iterations нельзя делить на
длину исходного текста для получения точного коэффициента символов на токен.

После начала нативной сессии передаются новые дельты и результаты инструментов;
сохранённая нативная история не отправляется целиком заново на каждом ходе.
После reload используется её ID. При меньшем окне сводка может быть короче, но
источник и правила подготовки остаются общими; полный архив не пропадает.

## Нативное автосжатие

Внутри уже идущей сессии историю сжимает сам backend. Лимит передаётся в его
штатный механизм, чтобы длинная сессия не выросла дальше общего бюджета:

| Провайдер | Механизм | Поведение |
| --- | --- | --- |
| Codex | `model_auto_compact_token_limit` в `thread/start` и `thread/resume` | Передаётся, только если лимит ниже 90% реального окна; иначе действует порог Codex по умолчанию. |
| Claude | `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | Лимит ограничивается диапазоном 258 400–967 000 токенов, который поддерживает 1M-вариант Opus 5. |
| Coco | `CORTEX_AGENT_SUMMARIZATION_TRIGGER_THRESHOLD` при запуске CLI | Доля окна модели, 0,20–0,99. Сервер дополнительно ограничивает её: 75% для окон от 1M, 90% для меньших. |
| Cursor | — | Лимит задаёт бюджет передаваемой истории; внутреннего порога Cursor расширение не настраивает. |

Порог Coco задаётся при старте процесса. При смене лимита простаивающие процессы
с прежним порогом освобождаются; следующий ход загружает сохранённую нативную
сессию по ID. Процесс с активным запросом не прерывается: он перейдёт на новый
порог после завершения хода. Модели всех провайдеров обновляются в VS Code сразу;
активные запросы Cursor при этом не прерываются.

## Статус Cursor

Профиль Cursor считается онлайн, если его каталог моделей с API-ключом успешно
загрузился за последние 15 минут, даже когда отдельная проверка доступности не
ответила. Проверка Cursor использует тот же таймаут 15 секунд, что и загрузка
каталога (раньше 5 секунд). Причина статуса Offline видна во всплывающей
подсказке профиля в Quick Access. Прочие API-профили по-прежнему следуют
результату проверки.

## Ошибка Coco после длительной работы

В исследованном случае CLI завершил запрос после 3 103 210 мс (около 51 минуты
43 секунд), получив `fetch failed` на `tool_results_submission` в 07:57:32 UTC
20 октября. Затем поздний возврат Chat встретил уже закрытый bridge и получил
generic `The Coco tool session is no longer active`. Это не доказательство
истечения срока активной сессии.

Теперь исходная ошибка сохраняется для поздних результатов в текущем Extension
Host, а причина закрытия записывается в `coco.turn.failed`. Транспорт не повторяет
завершённые действия автоматически. Для продолжения прерванной нативной сессии
нужен новый пользовательский ход; повтор старого tool batch не начинает новый run.

Дополнительно убран 30-минутный таймер **ожидающего инструмента**: подтверждение
или долгий инструмент считается активной работой. Явная отмена, смена провайдера
в том же чате и закрытие расширения всё ещё освобождают процесс. Освобождение
уже завершённого idle-процесса отличается от потери нативной истории: следующий
ход загружает сохранённый ID.

Якоря Coco теперь устойчивы к границам текстовых частей и обновлениям контекста
редактора. Совместимые прежние отпечатки мигрируют без нового cold prefill.

## Проверки

Регрессии покрывают переключение пяти адаптеров с reload и восстановлением
ранних сообщений, системные дубли, общий бюджет, текущие и исторические
изображения, миграцию native ID, ожидание без expiry и сетевую ошибку до возврата
tool result. Генерация сводки также проверяется на строке в 3 млн символов.

Во время проверки обнаружен отдельный performance bug: поиск путей в старом
генераторе сводки мог квадратично обрабатывать многомегабайтную строку без
переносов и подвешивать Extension Host. Анализ теперь ограничен фрагментом
32 768 символов и строками по 2 048 символов; полный текст остаётся в архиве.
