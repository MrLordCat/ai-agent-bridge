# Coco: диагностика ошибки после подготовки истории

Проверено 2026-10-19, AI Agent Bridge 1.18.11, Cortex Code 0.26.1019,
Snowflake VS Code 1.42.2, Windows, `claude-opus-5-5`. Исправление: 1.18.12.

## Подтверждённая причина

Сообщение `prepared 999,640 of 3,029,935 history characters` не было ошибкой.
Запрос дошёл до backend, который отклонил каталог инструментов:

`invalid tool name "mcp__vscode_chat__vscode_chat_configure_python_environment_cdfb233021", must be between 1 and 64 characters`

Полное имя содержит 69 символов. Мост ограничивал только часть имени, а SDK
добавлял `mcp__vscode_chat__`. Из 72 записанных имён 20 превышали ограничение;
максимум — 93 символа. Это отдельный дефект от обработки большого контекста.

В журнале `.snowflake/cortex/logs/coco.log` для сессии
`4952956b-83ff-4030-b76b-b91db4b67f63`:

- 18:36:44 UTC: 115 инструментов вместе со встроенными инструментами CLI,
  размер HTTP body 3,056,127 байт.
- 18:36:45 UTC: HTTP 400 / Snowflake 399515; CLI отсоединил thread и повторил
  запрос с полной историей. Этот fallback не означает успешный ответ модели.
- 18:36:46 UTC: HTTP 200, затем ошибка имени в SSE, request ID
  `3cdcfe77-42a0-4f93-8f88-6d1e1ec59556`.
- После ошибки bridge прервал run; в журнале появились `interrupt` и
  `user_interrupt`. Они следуют за ошибкой каталога и не являются её причиной.
- В native history сохранился текст `Error: invalid tool name ...`.

Надписи `Recovered from a request error` сами по себе не подтверждают, что
inference успешно завершился. Для этого нужны ответ/результат native run.

## Воспроизведение и проверка

`scripts/coco-request-repro.mjs` читает записанные SDK-имена указанной сессии.
При `--run` отправляет только диагностический запрос. Все callback-действия
заблокированы; вместо не сохранившихся исходных schemas используются инертные
object schemas. Содержимое переписки и ключи доступа в вывод не печатаются.

| Сценарий | Данные | Результат |
|---|---|---|
| До исправления | 72 исходных имени, короткий prompt, без истории | Та же ошибка имени; request ID `84a5110e-429c-4628-9a06-81cec30a3d88`, 0 вызовов действий |
| Исправленные имена | 72 имени, полный namespace максимум 64, короткий prompt | Успех, 13.6 с, 0 действий |
| Исправленные имена + большой input | 1,015,904 символа текста из сохранённого native user message | Контрольный ответ, 25.1 с, 0 действий |
| Resume после ошибки | Отдельная диагностическая сессия с прежним отказом, исправленные имена | Успех, 15.4 с, 0 действий |

Исходный дефект воспроизведён до изменения генератора. После исправления
`old-names` останавливается локальной проверкой без запуска inference.
Режимы `fixed-short` и `fixed-history` используют тот же алгоритм ограничения
имён, что и мост. `--resume-session` задаёт отдельную диагностическую сессию
для проверки восстановления. Без `--run` модельных запросов нет.

Граница доказанного: ошибка длины имени подтверждена независимо от контекста.
Проверки не воспроизводят исходные tool schemas, работу всех инструментов или
ручное переключение в UI. Генератор проходит unit-тесты маршрутизации длинного
имени обратно в исходный VS Code tool; остальные схемы при этом не изменяются.
Предыдущий live-тест с короткими именами не проверял данный дефект каталога.

## Изменения и диагностика

- Допустимая длина alias вычисляется после вычитания SDK namespace из 64.
  Стабильный hash suffix сохраняет различимость похожих имён.
- Перед new/load SDK проверяются длина, символы и уникальность полных имён.
- В журнал расширения добавлены `coco.request.prepared` и
  `coco.request.failed`: request ID, transport, tool count, максимальная длина,
  размер prompt, изображения, compaction и санитизированная ошибка.
  Сам prompt в эти события не записывается.
- Воспроизводитель и тесты явно разделяют успешный ответ, локальный отказ и
  backend error, вместо проверки одного лишь открытия процесса.
