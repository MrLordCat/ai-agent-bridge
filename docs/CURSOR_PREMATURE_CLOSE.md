# Cursor: Premature close после завершённого инструмента

Проверено 2026-10-19, локальное исправление 1.18.6, SDK 1.0.37.

## Подтверждённые данные

Ошибка `cb7e96a5-c096-4344-a902-8e1ff99e38dd` соответствует прерванному
native run `run-3696fbd6-4137-492e-86bd-bbd3010d430d`, turn 19 того же
агента, который успешно завершил turns 17 и 18 после исправления ID чата.

- Начало: 09:56:09.859 UTC, конец: 10:48:30.779 UTC — около 52 минут.
- SDK сохранил ошибку `[unknown] Premature close` без usage и причины
  завершения сетевого потока. Это не ошибка лимита 64 000 символов.
- Последнее событие callback: 10:48:29.900 UTC. Статус ERROR появился
  в 10:48:30.250 UTC, через 350 мс после его выдачи.
- Native checkpoint содержит 37 завершённых callback-вызовов, без pending
  инструментов. В SDK event log есть ещё один вызов с теми же именем и
  аргументами, что 38-й вызов в истории VS Code.
- Все 38 вызовов имеют результаты в видимой истории VS Code. Последний
  результат не успел попасть в native checkpoint.

SDK использует сетевой Connect-транспорт. Какая сторона и по какой причине
закрыла поток, эта ошибка не сообщает. Нет подтверждения лимита длительности,
отказа авторизации или завершения отдельного CLI-процесса. Перехват ошибки
расширением не может гарантированно устранить будущие сетевые обрывы.

## Что мешало продолжению

До 1.18.6 автоматическая проверка требовала точного равенства всех callback
вызовов checkpoint и видимой истории. В случае 37/38 она отвергала пригодный
checkpoint. Оставалась более старая завершённая точка, а повтор результата
инструмента возвращал сохранённую исходную ошибку. Эти повторы не запускали
дополнительный model run.

## Восстановление

На следующем новом пользовательском сообщении расширение:

1. Проверяет завершённость всех инструментов внутри native checkpoint.
2. Сопоставляет дополнительные SDK events с вызовами и готовыми результатами
   видимой истории по имени, аргументам и количеству, в пределах того же run
   и привязки workspace/profile/model/chat.
3. Восстанавливает native checkpoint. Только дополнительные завершённые
   действия и их результаты передаёт как явно обозначенную историю, с указанием
   не выполнять их повторно. Остальные 37 результатов повторно не отправляются.
4. После успешного продолжения удаляет служебные ссылки на этот хвост.

Отсутствующий результат, противоречащие аргументы или неразличимые одинаковые
вызовы между checkpoint и хвостом не допускают такого восстановления.
Если уже сохранённые recovery-ссылки не найдены в истории, inference не
начинается, а checkpoint и ссылки сохраняются для следующей попытки.
Служебные записи содержат только call IDs, а не аргументы или результаты.
Результаты уже находятся в общем локальном журнале Chat.

После установки выполните **Developer: Reload Window**, затем отправьте
в сбойном чате новое сообщение, например: «Продолжи с последней операции,
учти уже выполненные инструменты». Автоматический повтор старого пакета
результатов по-прежнему возвращает исходную ошибку; новая генерация требует
нового пользовательского хода. Полный холодный перенос истории не выполняется.

## Проверки

На реальном локальном журнале совпали все 38 вызовов: 37 внутри checkpoint,
один вне него. Дополнительно настоящий SDK восстановил того же агента с
этим checkpoint на временной копии хранилища. Байты snapshot не изменились,
оригинальные файлы остались неизменными. Сеть была запрещена: ноль сетевых
обращений и запросов генерации. Server cache hit этим не измерялся.

Автотесты проверяют конфликтующие SDK events, отсутствующие и дублированные
результаты, повтор старой ошибки, reload, сохранение recovery-ссылок при ошибке
до inference и однократную передачу только недостающего результата.

Полные проверки 1.18.6: **735 passing, 8 pending** на VS Code 1.131.0;
**733 passing, 10 pending** на установленной VS Code. TypeScript, ESLint,
metadata и git diff --check прошли. Платные model smoke tests не запускались.
