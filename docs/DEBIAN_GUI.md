# Interactive Debian desktop in Docker

This runs the Microsoft VS Code desktop application in Debian 12 with XFCE.
noVNC displays the desktop in a browser. AI Agent Bridge is not preinstalled,
so the VSIX installation and subsequent reloads can be tested manually.

## Start on Windows / Docker Desktop

Build the GUI image from the repository:

```powershell
docker build -f Dockerfile.gui -t ai-agent-bridge-debian-gui .
```

Use the Linux x64 VSIX from the 1.17.3 release or the locally verified package:

```powershell
$vsix = (Resolve-Path .\artifacts\debian\llama-vscode-chat-1.17.3-linux-x64.vsix).Path
docker run -d --name ai-agent-bridge-debian-gui --shm-size=1g `
  -p 127.0.0.1:6080:6080 `
  --mount "type=volume,source=ai-agent-bridge-debian-gui-home,target=/home/node" `
   --mount "type=bind,source=$vsix,target=/packages/llama-vscode-chat-1.17.3-linux-x64.vsix,readonly" `
  ai-agent-bridge-debian-gui
```

Open [the Debian desktop](http://127.0.0.1:6080/vnc.html?autoconnect=true&resize=scale).
The port is bound only to the Windows loopback address.

The desktop runs as UID 1000. Files, profiles, accounts and installed extensions
under `/home/node` persist in the named Docker volume. Windows accounts and
credential folders are not mounted.

## Install and check the extension

1. In VS Code, open **Extensions** and its **…** menu.
2. Choose **Install from VSIX…** and select
   `/packages/llama-vscode-chat-1.17.3-linux-x64.vsix`.
3. Run **Developer: Reload Window**.
4. Reload after the automatic patch notification.
5. Check Quick Access and **AI Agent Bridge: Show Copilot Chat Patch Status**.
6. Configure the provider you want to test. Firefox is available for account
   sign-in and OAuth callbacks inside the container.

Use the noVNC sidebar's clipboard panel to paste text. Alt+Shift switches the
US/Russian keyboard layout. The desktop contains a short README and a shortcut
to the mounted VSIX folder.

A model server running on Windows is available from the container at
`host.docker.internal:<port>`. The container's `localhost` refers to Debian.

## Application ownership

The default **VS Code (user-owned)** launcher uses `~/apps/vscode`. Its
application files are writable, so startup patches can apply without root.

**VS Code (system-owned)** uses root-owned `/opt/vscode-system` and a separate
profile. Extensions are shared through `--extensions-dir`. This window
reproduces the read-only application case.

To test the extension's no-root migration command, run
**AI Agent Bridge: Prepare User VS Code (Linux, no root)** from the system-owned
window. In this Docker fixture, open the resulting copy from a terminal with:

```sh
~/.local/bin/code-ai-agent-bridge --no-sandbox --disable-gpu ~/workspace
```

The GUI fixture passes `--no-sandbox` to Electron because Docker's namespace
sandbox is unavailable. The production launcher generated by the extension
does not add this flag.

## Test administrator patching with su

The Debian fixture has su, but neither sudo nor pkexec. Its root password is
initially locked. To enable a manual authorization test, set a root password in
your Windows terminal. Copy the locally built VSIX if it is not already in
the container:

```powershell
docker cp .\artifacts\debian\llama-vscode-chat-1.17.3-linux-x64.vsix ai-agent-bridge-debian-gui:/packages/
docker exec -it --user root ai-agent-bridge-debian-gui passwd root
```

Type the password directly into that terminal. Then install
`/packages/llama-vscode-chat-1.17.3-linux-x64.vsix` in the GUI, reload the
system-owned VS Code window, and run **AI Agent Bridge: Apply Copilot Chat Patch**.
Choose **Apply patches with administrator rights**, then **Run su in Terminal**.
Enter the root password in the Debian terminal and reload after success.

The extension generates the complete `su - root -c` command; replacing sudo
with su by hand would treat the command path as a username. A failed attempt
offers **Retry in Terminal**. **Apply Patch** in Quick Access reopens the same
retry workflow; **Close Attempt** discards it and starts a fresh one.
The password survives a stop/start of this
container, but recreating it resets root's password even when the home volume
is retained. The no-root migration option requires no root password.

## Stop, resume and diagnose

```powershell
docker stop ai-agent-bridge-debian-gui
docker start ai-agent-bridge-debian-gui
docker logs --tail 20 ai-agent-bridge-debian-gui
```

Desktop, VNC and VS Code logs are under `~/gui-logs`. Removing the container
preserves the named volume; removing that volume also removes saved profiles.
The existing headless verification image and driver remain separate.
