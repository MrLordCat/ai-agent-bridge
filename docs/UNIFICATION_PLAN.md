- Сохранить vendor, ID моделей, профили, ключи и действующие настройки.
- Общие механизмы вынести в компоненты; детали HTTP, SDK, ACP и app-server
  оставить в адаптерах. Использовать существующие нормализаторы и проверки.
- Сохранять нативное исполнение инструментов VS Code, изоляцию чатов,
  отмену, ограничения очередей и provider-specific восстановление сессий.
- После каждого этапа выполнять компиляцию и относящиеся к нему тесты.
  Отмечать пункт завершённым только после его реального подключения к коду.
- Завершить полной проверкой, локальным patch-обновлением и установкой VSIX.

- [x] 1. Реестр и контракт провайдера.
  - Общая идентичность источников и регистрация адаптеров вместо нескольких
    списков маршрутизации, группировки и subscription-status.
  - Подключить Composite, Directory и группировку моделей; сохранить legacy ID.
  - Проверить discovery с частично недоступным провайдером, маршрутизацию,
    совпадающие названия профилей и неизвестный источник.
- [x] 2. Метаданные, состояние и UI.
  - Общие ModelDescriptor/ProviderSnapshot и преобразование к VS Code metadata.
  - Общая арифметика рабочего окна и выходного резерва с политиками транспорта.
  - Убрать позиционные зависимости Quick Access, передавать состояние объектом.
  - Метрики привязать к source ID; бюджет, monthly usage и квоты различать.
  - Проверить контекст, reasoning, возможности и изоляцию метрик API-профилей.
- [x] 3. Кеши ресурсов.
  - Общий TTL/in-flight/revision-кеш для бюджета и каталогов.
  - Обновление credentials инвалидирует старое поколение; отмена одного
    потребителя общего запроса не отменяет остальных.
  - Проверить force refresh, поздний ответ, повторный запрос и смену ключа.
- [x] 4. Фасад API-источников и транспорты.
  - Вынести выбор Cursor/HTTP в отдельный маршрутизатор источников.
  - Подключить discovery, respond, token count и disposal через контракт адаптера.
  - Сохранить HTTP request shape, специфичные настройки и SDK lifecycle.
- [x] 5. Общий контроллер инструментов.
  - Вынести управление pending calls, границей ответа, завершением и буфером.
  - Подключить Cursor/Coco, затем общую механику Claude/Codex.
  - Оставить кодеки, native session recovery и таймаут-политики в адаптерах.
  - Проверить выдачу один раз, батчи, неполные/повторные результаты, отмену,
    поздний callback, продолжение и освобождение runtime.
- [x] 6. Финальная проверка и установка.
  - Линтер, полный набор тестов и диагностика редактора.
  - Документация изменений, patch-версия, compile → package → install.
  - Проверить установленную версию, source: vsix и совпадение runtime-файлов.

## Критерий завершения

Все этапы подключены и проверены. Новый адаптер регистрируется через общий
контракт; маршрутизация и базовые представления используют реестр/дескрипторы.
Общий кеш и контроллер действительно используются существующими интеграциями.
Проверенные настройки, идентификаторы и поведение сохраняются. План содержит
результаты проверок и установленную версию.

  Compile/lint прошли; 235 проверок адаптеров прошли до корректировки старой
