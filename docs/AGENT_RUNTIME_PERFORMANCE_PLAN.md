# План: производительность во время работы агентов (1.18.17)

Основание: аудит 2026-10-20 (лог сессии 148 мин, замеры на этой машине).
Время активации вне рамок плана.

## A. Целостность патча Copilot (критично)

Факт: в бандле Copilot стоит v22, расширение ожидает v25. «Оригинальный»
бэкап уже содержит маркер v22, патчер обновляет из него и падает
(`extension endpoint full context budget was not found`), ошибка подавляется
после первого показа. Нет v23–v25: исправления субагента, границ сохранённых
результатов инструментов, MCP `prefixItems`.

- A1. Бэкап с любым маркером `llama-vscode-chat:` не считается оригиналом:
  статус сообщает «backup contaminated», применение падает с понятной ошибкой
  и инструкцией, а не с ошибкой якоря.
- A2. Бэкап создаётся только из файла без маркеров; файл с маркером никогда
  не копируется как оригинал.
- A3. Межпроцессная блокировка на время применения (lock-файл `wx`,
  устаревший старше 2 минут снимается), чтобы два окна после обновления VS Code
  не патчили бандл одновременно.
- A4. Подпись подавления повторной ошибки включает версию расширения:
  новая версия снова показывает сбой.
- A5. Патч v26: запрос субагента не меняет «модель главного агента» в
  `getChatEndpoint` Copilot (иначе каждое чередование моделей родителя и
  субагента вызывает `onDidModelsRefresh`). Якорь необязательный: если его нет,
  остальной патч применяется.
- A6. Восстановление этой установки: получить чистые файлы точной сборки
  1.141.1 (`7baac39ec3`), сверить workbench с чистым `.bak`, заменить
  испорченные бэкапы (старые сохранить), применить v26, перезагрузить окно.
  Выполнено 2026-10-20: архив сборки с `update.code.visualstudio.com`, SHA-256
  workbench совпал с `.bak` (`1ca421d0…`), испорченные файлы лежат рядом
  с суффиксом `.contaminated-20261020`.

## B. Шторм опросов каталога моделей

Факт: 431 опрос за 20 минут работы одного субагента, пачки по 20–35 опросов
каждые ~33 с, медиана пачки 1 с, всего 77 с работы хоста расширений.

- B1. `ProviderRegistry.models`: один общий запрос на всех ожидающих и кэш
  на 3 с; сбрасывается событием изменения любого провайдера.
- B2. HTTP-провайдер: недоступный источник (каталог и `/slots`) не
  опрашивается повторно до истечения паузы 15 с → 30 с → 60 с. Пауза
  сбрасывается при `refreshLanguageModelChatInformation` и при успехе.
- B3. ~~`getModelSources()`: кэш до изменения секретов, настроек `llamacpp` или
  профилей API.~~ Не делается: источники зависят от workspace-настроек и
  доверия к URL без события изменения, и кэш может отправить ключ на старый
  адрес. После B1 чтение секретов для каталога и так идёт один раз на пачку.

## C. Перерисовки UI на живых обновлениях

- C0. Quick Access на каждой пересборке вызывает `getCopilotPatchStatus`:
  читает и хеширует бандлы Copilot (18.8 МБ) и workbench (19.4 МБ) —
  ~110 мс синхронно на потоке хоста расширений (замер). Статус кэшируется по
  `mtime`/размеру файлов, без SHA-256; поиск бандла кэшируется.
- C1. Quick Access: отложенное обновление (~200 мс, последнее событие
  выигрывает) вместо полной пересборки на каждое событие.
- C2. Статусы подписок: каталог провайдеров и панель менеджера обновляются
  только при смене `state`/`summary`; живые тики Codex (каждые 200 мс) только
  обновляют дерево через C1.
- C3. Живой отчёт сессии: запись не чаще раза в 2 с, по одной за раз
  (последнее состояние дописывается при выгрузке); панель отчёта не чаще
  раза в 500 мс.

## D. Фоновая нагрузка и рост

- D1. Codex: минутный цикл keepalive не делает сетевых запросов, когда
  keepalive выключен; таймер `unref` и очищается в `dispose()`.
- D2. Общий журнал: ключи сообщений кэшируются по объекту сообщения
  (`WeakMap`), ранее сохранённая история не хешируется на каждом шаге.
- D3. Архивы истории Coco: при старте удаляются файлы старше 14 дней
  (фоново, без блокировки активации).

## E. Мёртвый код
