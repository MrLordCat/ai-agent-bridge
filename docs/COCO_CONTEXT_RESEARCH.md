# Coco: почему большой чат может терять контекст

Обновление: причины ниже зафиксированы для 1.17.15. В 1.17.16 реализованы
постоянные/восстанавливаемые сессии, журнал переключений, перенос всей доступной
истории и нативные cache-счётчики. Текущее поведение и реальные проверки:
[COCO_CONTINUITY.md](COCO_CONTINUITY.md).

Проверено 2026-10-15 для AI Agent Bridge 1.17.15 и CLI Cortex Code
v0.26.1015 из Snowflake VS Code 1.42.2, Windows x64. Пользователь отметил
Claude Opus 5.5. Код управления контекстом Coco в этом патче не менялся.

## Основной вывод

Ощущение потери контекста имеет подтверждённую причину в мосте. Модель получает
сокращённую текстовую историю, а новый пользовательский запрос создаёт новую
ACP-сессию. Опущенные требования и факты не восстанавливаются автоматически.
Это ограничение интеграции применяется и к Opus 5.5; само по себе оно не
свидетельствует о плохой памяти или малом нативном окне этой модели.

## Какие ограничения действуют

| Уровень | Подтверждённое поведение | Следствие |
|---|---|---|
| Окно модели | Snowflake/runtime определяет настоящий предел. `usage_update.size` сообщает его после появления телеметрии | Настройка расширения не увеличивает серверное окно |
| Окно для VS Code | До телеметрии используется `cocoContextLength`, по умолчанию 128 000 токенов. Наблюдённое окно хранится в памяти расширения для ID модели | VS Code может передать провайдеру уже ограниченную историю; после перезапуска снова действует fallback |
| Резерв ответа | Карточка резервирует до 16 384 токенов для ответа | Эти токены не относятся к входному контексту. Это объявленный резерв, а не доказанный серверный предел вывода Opus |
| Текст отправляемой истории | Не более 500 000 символов; бюджет дополнительно зависит от окна, схем инструментов и резерва инструкций | Даже большое нативное окно не используется полностью для истории |
| Старые сообщения | Сохраняется начало и недавний хвост. Между ними сообщения могут быть удалены; сохранённые длинные сообщения тоже сокращаются | Требование или факт из середины может отсутствовать полностью |
| Результат инструмента | `convertCocoToolResult` оставляет не более 100 000 символов, беря начало и конец | Середина прочитанного файла, diff или вывода команды может пропасть даже до сокращения всей истории |
| Текущая сессия | Результаты инструментов продолжают тот же ACP prompt. Следующий новый пользовательский запрос создаёт новую сессию | Серверная история предыдущего запроса не дополняет потерянную часть сериализованной истории |
| Представление истории | Сообщения и tool calls/results объединяются в текст с метками User/Assistant внутри нового prompt | Модель видит реконструкцию разговора; это не восстановление оригинальной структурированной сессии |

## Сколько текста действительно уходит

Провайдер вычисляет бюджет символов по формуле:

`min(500000, max(4096, (maxInputTokens - toolTokens - 8192) * 3))`

`toolTokens` — оценка размера JSON-схем инструментов в символах / 4.
При fallback 128 000 и резерве ответа 16 384, даже без инструментов:

`(128000 - 16384 - 8192) * 3 = 310272` символа.

Подсчёт токенов в мосте приблизительный: текст / 4. Поэтому этот пример
соответствует примерно 77 568 оценочным токенам истории, не считая политик,
схем и прочих данных CLI. Это не измерение токенизатора Opus. Для русского
текста, кода и JSON соотношение отличается. Ограничение в 500 000 символов
остаётся даже при настройке большого окна.

Общий предел относится к тексту: изображения сохраняются отдельными ACP
блоками и также потребляют настоящее окно модели. Это ещё одна причина не
приравнивать количество символов к гарантированному числу доступных токенов.

При сокращении истории первое сообщение получает до 1/5 бюджета, каждое
сохранённое старое сообщение — до 16 384 символов. Текст между началом и
концом большого сообщения удаляется. Для результатов инструментов после
последнего пользовательского запроса действует дополнительная граница
`min(32768, budget / 8)`. Текущий пользовательский текст сохраняется целиком;
если он сам не помещается, возвращается ошибка с просьбой уменьшить запрос.
Алгоритм не создаёт смыслового резюме удалённых сообщений.

## Воспроизведение на текущей реализации

Скомпилированный `serializeCocoMessages` вызван напрямую с синтетическими
сообщениями; для автономного запуска подставлены только классы частей VS Code
и неиспользуемые в сериализации импорты. Сетевых запросов к модели не было.

| Проверка | Результат |
|---|---|
| История 1 200 530 символов при бюджете 310 272 | Отправляется ровно 310 272 символа |
| Маркер первоначальной инструкции | Сохранён |
| Маркер последнего запроса | Сохранён |
| Обязательное требование в сообщении №13 | Удалено |
| Результат инструмента 120 016 символов с фактом в середине | Факт удалён, остаётся маркер усечения |

Это доказывает возможность потери информации на входе. Оно не измеряет
качество ответов Opus и не подтверждает, что каждая замеченная пользователем
ошибка вызвана именно этим механизмом.

## Что подтверждено для самого Coco

Официальная [справка CLI](https://docs.snowflake.com/en/user-guide/cortex-code/cli-reference)
описывает сохранение контекста между обменами, `/resume`, `/fork` и локальное
хранилище сессий. Из справки нельзя вывести точный размер окна Opus 5.5 для
конкретного аккаунта Snowflake.

Нативные `initialize` и `session/new` проверены через наш ACP-клиент без
`session/prompt` и без генерации:

- CLI объявил `loadSession: true`, поддержку списка/закрытия сессий и изображений.
- Каталог `configOptions.model` содержит `claude-opus-5-5` / Claude Opus 5.5.
- Ответ создания сессии не сообщил размер окна. Точный лимит Opus 5.5 в этой
  проверке не измерен; для него требуется реальная `usage_update` телеметрия.
- Наш клиент использует `session/new`; методов загрузки/возобновления сессии
  в нём сейчас нет.

В статической реализации установленного CLI присутствуют собственные
настройки суммаризации (`autoCompactThreshold`, значение по умолчанию 0.9).
Путь формирования телеметрии порога учитывает величину окна; это внутренняя
деталь версии CLI, не обещание фиксированного размера или момента compaction
для любой модели. Сам цикл сжатия на длинном реальном запросе не запускался.
Суммаризация помогает продолжать сессию в конечном окне, но тоже теряет
детали и не восстанавливает текст, который мост вообще не отправил.

Отдельный предел 4 000 000 символов в ACP-клиенте ограничивает накопленный
буфер входящих данных CLI, а не размер истории, отправляемой в модель. Он
вызывает явную ошибку oversized ACP message, а не тихую потерю старого чата.

## Что это означает для работы

- Opus может повторять исследование, забывать прежние ограничения и предлагать
  уже отвергнутые решения, если соответствующие сообщения не дошли до него.
- Факт в середине большого файла может отсутствовать даже при небольшом чате:
  срабатывает отдельное сокращение tool result. Файл нужно читать выборочно.
- В одном активном агентном цикле сохранность лучше: работает та же ACP-сессия.
  На следующем пользовательском запросе мост снова собирает историю заново.
- Увеличение `cocoContextLength` может ослабить раннее ограничение VS Code,
  но не снимает 500 000 символов, не отменяет усечение результатов и не
  подтверждает допустимость такого окна сервером.
- До исправления критичные требования и текущее состояние стоит хранить
  в небольшом файле проекта и явно перечитывать его при продолжении задачи.
  Новый чат помогает только вместе с содержательным переносом состояния.

## Приоритет улучшений

1. P1: сохранять ACP-сессию по разговору и возобновлять её при новых запросах.
   Проверить изоляцию workspace/модели/connection, отмену, обновление каталога
   client tools, порядок истории и перезапуск расширения. Наличие
   `loadSession: true` ещё не доказывает, что всё это работает автоматически.
2. P1: заменить молчаливую обрезку середины управляемым резюме с сохранением
   цели, решений, ограничений, изменённых файлов и незавершённых действий.
   Пользователь должен видеть, что история сокращена.
3. P1: согласовать бюджет VS Code, фактическую телеметрию модели и резервы;
   не обещать окно на основании имени Opus или значения настройки.
4. P2: отдавать большие результаты инструментов через файл/ссылку и точечное
   перечитывание; явно сообщать модели, какой участок результата недоступен.
5. P2: проверить длинный сценарий с контрольными фактами в начале, середине
   и конце, несколькими пользовательскими запросами, compaction и reload.

В 1.17.15 выполнены исследование и удаление Cursor Budget. Перечисленные
изменения архитектуры Coco остаются дальнейшей работой.
